# Public API, SDK, and exports

PR 14 establishes the stable public integration surface for the Civic Registry
& Transparency Engine.

The versioned public API is rooted at:

```text
/api/v1
```

The API is read-only and uses the same lifecycle, disclosure, relationship,
evidence, history, and deadline boundaries as the public web application.

## Versioning

The first public API version is `1`.

Every JSON envelope includes:

```json
{
  "apiVersion": "1",
  "data": {}
}
```

Errors use the same version marker:

```json
{
  "apiVersion": "1",
  "error": {
    "code": "record_not_found",
    "message": "The requested public record does not exist."
  }
}
```

Responses also include:

```text
X-API-Version: 1
```

Breaking public-contract changes should ship under a new API version rather
than silently changing `/api/v1`.

## CORS

The public API is intentionally readable cross-origin.

Versioned API responses include:

```text
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, OPTIONS
```

The API does not expose authenticated write operations.

## Endpoints

### API metadata

```text
GET /api/v1
GET /api/v1/openapi.json
```

### Registries

```text
GET /api/v1/registries
GET /api/v1/registries/{registryId}
```

Registry metadata exposes configured public structure such as:

- record types and fields;
- search/filter/sort flags;
- public lifecycle statuses;
- relationship definitions;
- publicly visible deadline types.

Private lifecycle states and private deadline definitions are not emitted as
public policy metadata.

### Records and search

```text
GET /api/v1/registries/{registryId}/records
GET /api/v1/registries/{registryId}/search
GET /api/v1/registries/{registryId}/records/{recordId}
```

The records and search endpoints use the same query contract.

Common parameters include:

- `q` — full-text query;
- `type` — record type id;
- repeated `status`;
- repeated `tag`;
- `sort`;
- `order=asc|desc`;
- `page`;
- `pageSize`.

Configured field filters remain schema-driven:

```text
f_{fieldId}=value
from_{fieldId}=value
to_{fieldId}=value
```

Public search always uses the PR 11 public-safe search projection.

### Evidence

```text
GET /api/v1/registries/{registryId}/records/{recordId}/evidence
```

The endpoint preserves field/document disclosure controls and cannot return
hidden evidence or original artifact references for redacted documents.

### History

```text
GET /api/v1/registries/{registryId}/records/{recordId}/history
```

Historical snapshots are passed through the current public disclosure policy,
matching the PR 11 public-history rules.

### Relationships

```text
GET /api/v1/registries/{registryId}/records/{recordId}/relationships
GET /api/v1/registries/{registryId}/records/{recordId}/graph
```

Relationship traversal uses the same hidden-withholding protections as the
public site.

The graph endpoint supports `depth` up to 3 and repeated relationship
`type` filters.

### Deadlines

```text
GET /api/v1/registries/{registryId}/records/{recordId}/deadlines
```

Only deadline definitions explicitly configured as publicly visible are
returned.

## Public-safe record contract

Record endpoints return the already-projected public record plus disclosure
metadata.

The canonical internal record is never serialized directly by the versioned
API.

This means the API inherits:

- publication lifecycle visibility;
- whole-record withholding;
- field redaction/withholding;
- safe tags and external identifiers for placeholder records;
- current public-history projection;
- safe evidence/document references.

## Error contract

Machine-readable errors use:

```json
{
  "apiVersion": "1",
  "error": {
    "code": "invalid_search",
    "message": "The search request is invalid.",
    "issues": []
  }
}
```

Stable error codes include cases such as:

- `registry_not_found`;
- `record_not_found`;
- `invalid_search`;
- `invalid_export_format`;
- `invalid_export_limit`.

## OpenAPI

The OpenAPI 3.1 document is available at:

```text
GET /api/v1/openapi.json
```

The document is generated by `@civic-registry/api`, not by Next.js route
code. Downstream deployments can reuse the same contract package.

## Exports

```text
GET /api/v1/registries/{registryId}/export
```

Exports accept the same public search/filter query parameters plus:

- `format=json|ndjson|csv`;
- `maxRecords` from 1 through 10,000.

The default format is JSON.

The default maximum is 10,000 records.

Exports iterate through public search pages internally; they are not limited
to the first 100 search hits.

Response headers include:

```text
X-Export-Total
X-Export-Count
X-Export-Truncated
Content-Disposition
```

If the matching result set is larger than `maxRecords`,
`X-Export-Truncated: true` makes that explicit.

### JSON

JSON exports contain metadata and a `records` array.

### NDJSON

NDJSON emits exactly one public-safe registry record per line.

### CSV

CSV provides stable metadata columns followed by configured field columns:

```text
id
recordTypeId
status
visibility
createdAt
updatedAt
publishedAt
tags
externalIdentifiers
field.{fieldId}
```

Arrays/objects are JSON-encoded inside cells.

CSV text beginning with `=`, `+`, `-`, or `@` is prefixed with an
apostrophe to neutralize spreadsheet formula injection.

## TypeScript SDK

The package is:

```text
@civic-registry/sdk
```

Example:

```ts
import {
  CivicRegistryClient,
} from "@civic-registry/sdk";

const client = new CivicRegistryClient({
  baseUrl: "https://registry.example",
});

const registries =
  await client.listRegistries();

const results = await client.search(
  "public-document-catalog",
  {
    q: "annual report",
    status: ["published"],
    page: 1,
  },
);

const record = await client.getRecord(
  "public-document-catalog",
  "example-report",
);
```

The SDK accepts either a site root or an explicit `/api/v1` base URL.

It supports an injected `fetch` implementation and custom headers.

Public methods include:

- `listRegistries`;
- `getRegistry`;
- `listRecords`;
- `search`;
- `getRecord`;
- `getEvidence`;
- `getHistory`;
- `getRelationships`;
- `getGraph`;
- `getDeadlines`;
- `exportRecords`;
- `getOpenApiDocument`.

Non-success responses throw `CivicRegistryApiError` with:

- HTTP status;
- public error code;
- message;
- optional structured issues.

## Compatibility

The pre-existing unversioned JSON routes remain available in PR 14 so this
milestone does not introduce a gratuitous breaking change.

New integrations should use `/api/v1`.

## Deliberately deferred

PR 14 does not add:

- authenticated write APIs;
- API keys;
- rate-limit billing;
- webhooks;
- GraphQL;
- generated clients in languages other than TypeScript;
- bulk administrative mutation endpoints.

Those are not required for the public registry v1 contract and should be added
only when a real downstream application demonstrates the need.
